# Guided project onboarding

Run ai-setup onboard from the relevant checkout. Read existing agent instructions, project docs, and selected modules from ai-setup rules. Identify conflicting instructions explicitly and ask the project owner to resolve them before adopting a conflicting rule. Inspect actual manifests and source, trace critical flows to their boundaries, and sample relevant tests and conventions. In a monorepo, identify shared dependencies and examine only relevant packages. Distinguish verified facts, hypotheses, and open questions. Propose only useful knowledge records, cite source lines, and keep secrets out. Inventory existing rules, decisions, knowledge, and skills, including any additional locations supplied by the owner. Propose one consolidated structure, keep skills discoverable in native locations, and preserve useful content and recoverable originals. Never silently delete, overwrite, or make knowledge inaccessible. Review existing knowledge for overlap. Explain conflicting instructions simply, recommend a resolution, and obtain the owner's decision. Record project exceptions for future updates. Show the proposal to the owner and wait for explicit approval before writing. Use ai-setup onboard save to review and save approved records. Recheck the code before relying on prior knowledge.
